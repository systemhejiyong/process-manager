# 进程管理工具 冒烟测试

> 项目 process-manager，awaiting first build for smoke（首包未出，下列步骤待可运行构建就绪后执行并回填）。

目标：装包/解压后约 10 分钟内走通核心路径；任一步失败即判冒烟不通过，停止后续，保留日志。

## 前置
- GUI：Windows 或 Linux 桌面可安装包 / 可运行二进制
- CLI（仅 Linux）：`procman` 在 PATH 中，`procman --help` 可用
- 准备：一个可杀的测试进程；可选一个监听端口（如 5173）的 dev server

## GUI 冒烟（约 5 分钟）
1. 启动应用不闪退；顶栏权限文案正确（Win「以管理员身份重新启动」/ Linux「提权重新启动」）。
2. 点「刷新本机进程列表」，列表有数据，列含 PID/进程名/端口/项目目录/父进程/命令行/路径。
3. 进程名搜 `node`（或本机常见名），有结果；乱输无匹配名出现空态。
4. 若有监听端口：按端口查，显示占用进程 PID/命令行/项目目录（能推断时）。
5. 选中一行，下方相关进程区有内容（有父子/同路径时）；勾选后汇总文案正确。
6. 关闭单个自启测试进程，进程消失，操作日志有带时间戳记录。
7. （可选）勾选同名匹配 → 一键关闭 → 确认框含数量 → 确认后退出；4 秒内若被拉起日志有提示。

## CLI 冒烟（Linux，约 3 分钟）
1. `procman --help` 退出码 0。
2. `procman find --name <关键词>` 表格式有列；`--json` 为数组。
3. `procman find --port <端口>` 有/无占用行为符合（0 / 2）。
4. `procman kill <测试pid>` 进程退出；默认有约 4 秒 watch（或 `--no-watch` 立即返回）。

## 10-15 本机 Linux CLI 首轮（`target/release/procman`）

| 项 | 结果 |
|----|------|
| `--help` / 子命令 | 通过 |
| `find --name bash` | 通过（有结果） |
| `find --port 1340` | 通过（node 占用） |
| `find --port 59999` | 通过，退出码 2 |
| `--json` | 通过 |
| `related <pid>` | 通过 |
| `kill <sleep_pid> --yes --no-watch` | 通过 |
| `kill 0` / `kill 1` | 拦截提示通过；退出码现为 4（可再议是否应为 1） |
| **`find --name ___nomatch___`** | **失败 BUG-PM-001**：因匹配 cmdline，把自己列出来，退出码 0 |
| **`kill --name ___nomatch___ --yes`** | **失败 BUG-PM-001**：把自身杀掉，退出码 137；期望退出码 2 |

**BUG-PM-001（P0）**：`--name` 按命令行模糊匹配，导致搜索词出现在 argv 里的 `procman` 被命中；`kill --name` 会杀掉自己。PRD 要求按**进程名**模糊匹配。

### 10-15 复测 BUG-PM-001
- TC-C15：`find --name ___nomatch___` → 无匹配，退出码 2，通过
- TC-C16：`kill --name ___nomatch___ --yes --no-watch` → 无匹配，退出码 2，通过
- BUG-PM-001：**关闭**
