# 进程查找关闭工具 — PRD v0.1

> 日期：2026-10-14  
> 状态：草案（待确认产品名、首发平台）  
> 参考：用户提供的 Windows 工具截图「进程查找关闭工具」

## 1. 背景与目标

多个 Agent / 开发工具会拉起大量子进程（如 `node`、`python`），普通任务管理器很难看清：
- 某个端口被哪个项目占用
- 进程对应的项目目录是什么
- 一堆同名进程该关哪些、关完会不会被父进程立刻拉起

**目标**：做一个 Windows + Linux 桌面工具，按进程名 / 端口快速定位，展示项目目录与父子关系，支持单杀与批量关闭。

## 2. 用户与场景

| 用户 | 场景 |
|------|------|
| 本机开发者 / Agent 使用者 | 端口被占（如 5173），查是哪个项目 |
| 同上 | `node`/`python` 残留几十个，想按项目目录批量关 |
| 同上 | 关完后确认有没有被父进程立刻重启 |

## 3. 平台

- **必须**：Windows 10/11、主流 Linux 桌面（Ubuntu 22.04+ 等）
- UI 一套逻辑，系统差异放在进程/端口采集层
- Windows 支持「以管理员身份重新启动」（关服务/部分受保护进程需要）
- Linux：普通用户能杀自己的进程；杀他人进程需提权（pkexec/sudo），v1 可先提示权限不足

## 4. 信息架构（对齐截图）

### 4.1 顶栏
- 标题 + 一句话说明
- 当前权限状态：标准用户 / 管理员（或 Linux 的 root/elevated）

### 4.2 搜索区
1. **进程名搜索**：输入框 +「查找」+「刷新本机进程列表」
2. **端口查询**：输入框（例 5173）+「按端口查」
3. **操作**：
   - 勾选「一次关闭全部同名匹配」
   - 「一键关闭」（危险操作，红色）
   - 「以管理员身份重新启动」（Windows；Linux 对应「提权重新启动」）
4. 结果计数：如「显示 N 个进程」

### 4.3 主列表（匹配结果）

| 列 | 说明 |
|----|------|
| PID | 进程 ID |
| 进程名 | 如 `node.exe` / `node` |
| 监听端口 | 该进程监听的端口，多个用逗号；无则「—」 |
| 项目目录 | 从工作目录 / 命令行参数推断的项目根（见 §5） |
| 父进程 | 名称 + PID，如 `Cursor (140836)` |
| 命令行 | 完整启动命令 |
| 完整路径 | 可执行文件路径 |

支持按列排序；选中一行后在下方展开「相关进程」。

### 4.4 相关进程（批量）
- 展示与当前选中项相关的进程：父进程、子进程、同路径、同项目目录
- 勾选「一并关闭」；汇总「已勾选 M / N，一键关闭会一起结束」
- 列：关系、PID、进程名、完整路径、服务（Windows 服务名，无则空）

### 4.5 操作日志
- 带时间戳的操作记录（查找、关闭成功/失败、重启检测）
- 关闭后短时监控：默认 4 秒内若同名进程被重新拉起，写入日志提示

### 4.6 状态栏
- 当前状态文案 + 版本号

## 5. 「项目目录」推断规则（产品规则）

按优先级取第一个存在的路径：
1. 进程当前工作目录（cwd），若像源码项目根（含 `package.json` / `pubspec.yaml` / `Cargo.toml` / `.git` / `pyproject.toml` 等）则用之
2. 命令行里显式路径参数（如 `--cwd`、脚本所在目录）
3. 可执行文件所在目录（兜底，并标注「仅可执行目录」）

推断失败时显示「—」，不编造路径。

## 6. 功能需求

### P0（首版必须）
- F1 刷新并列出本机进程
- F2 按进程名模糊搜索（大小写不敏感）
- F3 按端口精确查询（谁在听该端口）
- F4 主列表展示 §4.3 各列
- F5 选中后展示相关进程并可勾选
- F6 关闭单个进程
- F7 「一次关闭全部同名匹配」+「一键关闭」
- F8 关闭后 4 秒内检测同名是否被重新启动并写日志
- F9 操作日志
- F10 Windows / Linux 均可运行（同一套交互）

### P1（紧随其后）
- F11 按「项目目录」筛选 / 分组
- F12 收藏常用进程名、常用端口
- F13 导出当前列表为 CSV
- F14 Windows：一键提权重启；Linux：提权重启或明确提示权限不足

### P2（可后置）
- F15 服务列深化（停服务 vs 杀进程）
- F16 系统托盘常驻
- F17 多语言

## 7. 交互与安全

- 「一键关闭」二次确认：文案需写明将结束的进程数量；勾选同名匹配时额外提示
- 不提供「强制结束系统关键进程」白名单绕过；对 `pid 0/1`、系统关键镜像给出拦截提示
- 默认不自动刷新过频；手动刷新 + 查找时刷新
- 所有数据仅本机采集，不上传

## 8. 非目标（v1 不做）

- 远程机器进程管理
- 性能监控图表 / CPU 火焰图
- 替代完整任务管理器的全部能力
- macOS（若后续要做，另开版本）

## 9. 验收要点（摘要）

1. 查端口 5173，能显示占用进程的 PID、命令行、项目目录（能推断时）
2. 搜 `node`，列表含监听端口与父进程
3. 勾选同名匹配后一键关闭，目标进程退出；4 秒内若被拉起有日志
4. 相关进程表能勾选父/同路径进程一并关闭
5. 标准用户下对无权限进程关闭失败时，有可读错误，不静默失败
6. Windows 与 Linux 核心流程均可走通

### 12.1 Linux CLI（`procman`）— 首版必须

与 GUI 共用同一套查询/关闭能力，数据只在本机。

| 能力 | 约定 |
|------|------|
| 按进程名搜 | `procman find --name <关键词>`（模糊、大小写不敏感） |
| 按端口查 | `procman find --port <端口>` |
| 列出详情 | 默认表格式输出列：PID、进程名、监听端口、项目目录、父进程、命令行、完整路径；`--json` 输出 JSON 数组 |
| 关闭指定 | `procman kill <pid> [<pid>…]`；默认先 SIGTERM，失败可 `--force`（SIGKILL）；无权限非 0 退出并 stderr 说明 |
| 同名批量关 | `procman kill --name <关键词>`（等同 GUI「一次关闭全部同名匹配」）；执行前若非 `--yes` 则交互确认数量 |
| 相关进程 | `procman related <pid>` 列出父/子/同路径/同项目目录；`procman kill <pid> --with-related` 按与 GUI 相同关系一并结束（默认需确认） |
| 关闭后检测 | 默认监控 4 秒是否同名被拉起；结果写到 stdout；`--no-watch` 可关 |
| 刷新/全量 | `procman list` 列出当前用户可见进程（可加 `--name`/`--port` 过滤） |
| 退出码 | 0 成功；1 一般错误；2 无匹配；3 权限不足；4 部分关闭失败 |
| 帮助 | `procman --help` / 子命令 `--help` |

非目标（CLI v1）：Windows 命令行入口、守护进程、远程。

§10「是否需要附带 CLI」已关闭：Linux CLI 进首版。
